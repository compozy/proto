# ADR-001: One package with subpath exports

## Status

Proposed

## Date

2026-10-30

## Context

The gallery has five consumers of different parts: authoring types (prototype files), flow types, config,
the Vite plugin, the Node API/CLI, the MCP server and the remote review server. Pedro approved publishing
it as a public library (`@compozy/proto`, 2026-10-30).

## Decision

Publish one npm package, `@compozy/proto`, with subpath exports `.` (authoring), `/flow`, `/config`,
`/vite`, `/node`, `/server`, `/mcp`, and the `proto` bin. Heavy integrations are optional peer
dependencies: `playwright` (evidence), `postgres` (server storage), `@modelcontextprotocol/sdk` (mcp).
Versions stay 0.x and the surface is documented experimental until the three consumer migrations land.

## Alternatives Considered

### Alternative 1: Package family (`@compozy/proto-core`, `-vite`, `-cli`, `-server`)

- **Pros**: smaller installs per role; independent versioning.
- **Cons**: version skew between plugin, shell and store; more release work; users must pick packages.
- **Why rejected**: every consumer needs core + vite + cli together; the server is the only separable part
  and optional peers cover its dependencies.

### Alternative 2: Storybook addon

- **Pros**: ecosystem, MCP already exists (`@storybook/addon-mcp`).
- **Cons**: CSF model has no flows, roles, review threads or approval; heavy framework; Pedro decided to
  keep Storybook separate for now.
- **Why rejected**: the differentiators would fight the host model.

## Consequences

### Positive

- One install, one version, one changelog; consumers cannot mix incompatible pieces.

### Negative

- Install size includes the prebuilt shell; budget 400 KB gzip, enforced by a size check in the package
  build (slice 6) and verified by the packed-tarball adoption test.

### Risks

- Optional peers missing at runtime → mitigated by deterministic exit 3 errors with install commands.

## Implementation Notes

`packages/gallery` is renamed `packages/proto`; `package.json` `exports` + `bin`; built with `tsdown`
(Node entries) and Vite (shell bundle) into `dist/`.
