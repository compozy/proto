# ADR-002: Prebuilt, isolated shell; prototypes in consumer iframes

## Status

Proposed (revised after peer review round 1)

## Date

2026-10-30

## Context

All three copies render the shell with the host app's design system and compile it inside the app's Vite
config, filtering plugins by name; the shell also reaches into the iframe's `document` for picking and pins.
A library cannot depend on the consumer's components or styles, and a shell that touches the iframe's
document cannot sit on a different origin.

## Decision

The shell is a separate React app built at package build time into `dist/shell` with its own React, vendored
BnUI components and compiled CSS. It is served by the shell origin (dev Node server, static build, remote
server) and learns its environment only from `bootstrap.json` (mode, API base, events URL, render origin,
snapshot base). Prototypes render in iframes on the render origin, compiled by the consumer's Vite. The shell
and the render host communicate only through the typed postMessage protocol of ADR-008 — the shell never
reads an iframe's `document` or `window`.

## Alternatives Considered

### Alternative 1: Shell compiled in the consumer's Vite

- **Pros**: one bundle, shared React.
- **Cons**: the consumer's Tailwind/PostCSS/React Compiler apply to shell code; style collisions; the
  consumer must allow-list the package in its sources; the shell depends on `import.meta.hot`.
- **Why rejected**: it is today's coupling.

### Alternative 2: Shadow DOM shell in the same document as the prototype

- **Cons**: portals escape the shadow root; consumer global CSS leaks in; no origin isolation.
- **Why rejected**: brittle and insecure.

## Consequences

### Positive

- Identical shell in every project; consumers never compile it; the shell runs unchanged in dev, static and
  remote modes.

### Negative

- Two React copies in the page; picking and anchoring move into the render host.

### Risks

- Iframe count on the flow canvas → preview queue (≤ 3 loading, ≤ 12 kept).

## Implementation Notes

Shell components come from the `proto-shell` draft; BnUI sources vendored under `src/shell/ui` with provenance
headers. Portaled popups read tokens through `:root:has(.proto-shell)` as in the draft.
