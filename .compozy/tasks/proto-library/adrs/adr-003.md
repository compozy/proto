# ADR-003: One ReviewStore for local files and the remote server

## Status

Proposed

## Date

2026-10-30

## Context

reloaddev switches between local files and a remote API with `import.meta.env.PROD` checks in the shell
and a separate CLI code path; CompozyOS and stack are local-only. Pedro decided remote comments and
approval are in v1.

## Decision

Define `ReviewStore` (comments, attachments, reviews). `FileStore` implements it on repository files (v3
per-key JSON, owner-token lock, atomic writes — ADR-009); `HttpStore` implements it over the review API. The dev shell server (plain Node, not Vite middleware) and
the remote server mount the same fetch router, so the shell uses one HTTP client and the CLI/MCP pick the
store by `--remote`. One shared contract test suite runs against both implementations.

## Alternatives Considered

### Alternative 1: Remote-only (always a server, even locally)

- **Cons**: comments leave the repository; no PR review of comments; needs a database for local work.
- **Why rejected**: local files are a product feature.

### Alternative 2: Sync local ↔ remote

- **Cons**: conflict resolution, id remapping, two sources of truth.
- **Why rejected**: Non-Goal; a project chooses where a review happens.

## Consequences

### Positive

- Shell, CLI and MCP have one code path; behavior parity is testable.

### Negative

- Two hosts for one router (the dev Node shell server and the remote server) — mitigated by mounting the
  same fetch router in both, with the dev host adding the `Host`/`Origin` checks.

### Risks

- Divergent semantics → contract suite IT-021/IT-022.

## Implementation Notes

The dev shell server adapts Node `IncomingMessage` to `Request` and mounts the same fetch router as the
remote server, with `FileStore` storage and a shell-origin check instead of a principal. The store contract
suite runs against `FileStore`, `HttpStore` + `fileStorage` and `HttpStore` + `postgresStorage`; `ReviewStore`
covers the full attachment lifecycle (upload, claim, discard, read) and review transitions (ADR-009), and
`HttpStore` enforces the credential policy (HTTPS except loopback, no redirects with credentials).
