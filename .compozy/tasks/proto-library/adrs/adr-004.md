# ADR-004: proto.config.ts + proto.canvas.tsx replace three files

## Status

Proposed

## Date

2026-10-30

## Context

Stack apps opt in with `gallery.config.ts`, `vite.presentation.ts` and `preview/{canvas.tsx,gallery.css}`;
reloaddev hardcodes specs/roles in `contract.ts` and paths in discovery; CompozyOS hardcodes paths.

## Decision

`proto.config.ts` (data: title, globs, specs, roles, siteUrl, locale, guards, review, evidence) and
`proto.canvas.tsx` (`Canvas` providers, optional `Frame` chrome). The render host reuses the app's own
`vite.config.ts` (the `proto()` plugin is added there), so `vite.presentation.ts` and `gallery.css` are no
longer needed: app CSS is imported by `Canvas`.

## Alternatives Considered

### Alternative 1: Keep `gallery.config.ts` name and `preview/` folder

- **Cons**: three files for one concern; "gallery" no longer names the product.
- **Why rejected**: migration is automated (`proto migrate`), so the cleaner layout costs little.

## Consequences

### Positive

- Two files to adopt; everything else has defaults.

### Negative

- Existing copies must migrate (internal code, automated).

## Implementation Notes

zod schema for config; `loadProject` loads it with Vite's `loadConfigFromFile`-style bundling so TS works
in CLI and MCP.
