# ADR-005: CLI JSON is the agent contract; MCP and skills wrap it

## Status

Proposed

## Date

2026-10-30

## Context

Agents (CompozyOS open-design profile, Claude, Codex) already operate the gallery through the `proto` CLI
and project skills (`apply-prototype-comments`, `eng-prototype-comments`). Storybook 10.3 shows the value
of an MCP surface (list docs, preview, run tests).

## Decision

Every capability is a Node API function with a CLI verb whose `--json` output and exit code are the
canonical contract. `proto mcp` exposes the same functions as MCP tools returning the same JSON (no
approval tool). Skills `author-prototype` and `apply-prototype-comments` ship inside the package and are
installed by `proto init --skills`; they only reference public commands.

## Alternatives Considered

### Alternative 1: MCP-first

- **Cons**: not every agent harness has MCP; shell scripts and CI need the CLI anyway.
- **Why rejected**: CLI is the lowest common denominator; MCP is a thin wrapper.

## Consequences

### Positive

- Parity is testable (IT-015); skills stay short.

### Negative

- Two surfaces to document — generated from one command table.
