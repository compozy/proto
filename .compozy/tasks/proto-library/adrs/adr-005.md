# ADR-005: One capability catalog for the Node API, CLI and MCP

## Status

Proposed (revised after peer review round 1)

## Date

2026-10-30

## Context

Agents operate the gallery through the CLI and project skills; MCP is wanted for harnesses that prefer it.
Round 1 showed the hand-listed MCP tools and `ReviewStore` missed operations the CLI promised (attachments,
edit, reopen, delete).

## Decision

`src/capabilities/catalog.ts` lists every capability once (Node API function, HTTP route, CLI verb, MCP tool,
authority, intentional exclusions with reasons). CLI verbs and MCP tools are generated from it; their JSON
output and error codes come from the same functions and the shared error registry. MCP excludes only
approval, credentials, migration and process lifecycle. Store-backed tools take `remote?: boolean`. Skills
`author-prototype` and `apply-prototype-comments` ship in the package and reference only catalog commands;
they state that agents never approve. Evidence lives under `docs/design/<slug>/` (PNG and HTML) so the
open-design `lint_artifact` accepts it.

## Alternatives Considered

### Alternative 1: MCP-first

- **Why rejected**: not every harness has MCP; scripts and CI need the CLI.

### Alternative 2: Hand-written MCP subset

- **Why rejected**: drifts from the CLI (round 1 O-B008/A-B009).

## Consequences

### Positive

- Parity is structural and tested by iterating the catalog (IT-015).

### Negative

- The catalog is one more abstraction to maintain.
