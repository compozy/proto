# ADR-006: Shell visual contract — dark canvas, pink primary

## Status

Accepted (Pedro, 2026-10-30: "o design até ficou bom", completing the missing pages before implementation)

## Date

2026-10-30

## Context

The stack shell is plain (light gray, tiny flow nodes, weak hierarchy). Pedro shared a dark workflow-canvas
reference (lime accent) and asked for that style with pink as primary, built with reui-blocks/BnUI.

## Decision

The shell's visual contract is the `proto-shell` draft prototype (dark near-black dotted canvas, panels,
hairline borders, pink primary, mono kind eyebrows, icon rail, inspector with tabs, flow cards with live
previews, light theme mirror). It covers every `_uiux.md` surface; implementation matches it. The draft
lives in the stack template until slice 1 moves it into this repository's `apps/app` — the library
prototyping itself. The shell is built directly to this contract in Milestone 1 (ADR-007): rebuilding the
shell on vendored components is new code either way, so the redesign is not a separate product.

## Alternatives Considered

### Alternative 1: Keep the current stack shell look

- **Why rejected**: Pedro judged it weak.

### Alternative 2: Compact nodes without previews (closer to the reference)

- **Pros**: calmer canvas.
- **Cons**: loses the main value — seeing the screens in the journey.
- **Why rejected**: previews stay; compact mode may come later as a zoom level.

## Consequences

### Positive

- One reviewed visual source; real components, not HTML boards.

### Risks

- Contract drift between draft and shell → slice 1 and slice 3 each close with a review checklist per `_uiux.md` surface, walked in the gallery against the draft (no pixel diffing — visual regression is a Non-Goal).
