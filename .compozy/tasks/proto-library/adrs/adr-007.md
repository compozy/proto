# ADR-007: One spec, two milestones that each end drift

## Status

Proposed

## Date

2026-10-30

## Context

Round 1 found that the MVP (old slices 1–5) left all three copies in place, so it did not solve the
Motivating Problem, and that numbering differed between sections (O-B010). Opus proposed splitting into three
specs (extraction, remote review, shell redesign); Astra judged a staged program inside one spec sufficient
once slice outcomes are honest (A-N003).

## Decision

Keep one spec with one slice numbering and two milestones, each ending drift for the copies it can replace:

- **Milestone 1 (slices 1–6, MVP)** — package, render origin, shell built to the visual contract, local
  review loop, catalog/MCP, `init`, `migrate` for files, migration and deletion of the stack template and
  CompozyOS copies, static build. Exit: two copies deleted, their review history verified.
- **Milestone 2 (slices 7–9)** — review server, auth, credentials, `HttpStore`/`--remote`, `migrate remote`,
  migration and deletion of reloaddev's copy and API module. Exit: no copy left.

The shell redesign is not a separate product: decoupling the shell from each app's design system means
rebuilding it on vendored components, which is the same work as building it to the ADR-006 contract.

## Alternatives Considered

### Alternative 1: Three specs (extraction → remote → redesign)

- **Pros**: smaller documents; independent approvals.
- **Cons**: the extraction spec would rebuild the old shell on vendored components only to replace it in the
  redesign spec; contracts shared by all three (store, protocol, catalog, errors) would be split across
  documents.
- **Why rejected**: duplicated shell work and fragmented shared contracts; the milestone gates give the same
  sequencing.

### Alternative 2: Single MVP including remote review

- **Why rejected**: delays ending drift for the two local-only copies behind auth and Postgres work.

## Consequences

### Positive

- Each milestone deletes code; slice 1 has an honest outcome (adoption and browsing), slice 3 the first full
  review loop.

### Negative

- A long spec; tasks must cite sections precisely.
